# LLM Usage SwiftBar 多平台需求说明

## 1. 文档目的

本文件用于维护插件的产品需求与边界。  
README 仅用于安装与使用说明，不承载需求讨论。

## 2. 项目目标

将当前插件演进为通用的 SwiftBar 菜单栏用量插件，支持多平台接入与统一展示，便于后续贡献者快速扩展新平台。

## 3. 平台范围与优先级

### 3.1 当前目标平台

1. `new_api` 类第三方 token 供应商（优先）
2. `Cursor`
3. `Trae.ai`

### 3.2 接入策略

- 优先接官方或稳定接口。
- 非官方接口优先级低。
- 本地日志解析优先级低。
- 无法自动拉取时，允许手工配置窗口作为兜底。

## 4. 架构要求

### 4.1 总体原则

- 先统一架构，再逐个平台接入。
- Provider 适配层与渲染层解耦。
- 新平台应以最小改动接入，不影响已有平台。

### 4.2 展示层级

统一展示结构必须为：**平台 > 账号 > 窗口**。

### 4.3 主账号规则

- 支持指定主账号。
- 菜单栏顶部主指标取自主账号。

## 5. 用量窗口模型

统一支持六类窗口：

1. 日
2. 5小时
3. 周
4. 月
5. 自定义
6. 不重置

说明：

- 允许不同平台返回不同单位与字段。
- 以平台可得数据为准，不强行统一单位。

## 6. 配置与交互要求

### 6.1 配置入口

- 所有平台接入配置应通过 SwiftBar 图形交互完成。
- 不要求用户直接编辑配置文件。

### 6.2 账号能力

- 支持多账号并存（同平台可多个账号）。
- 支持账号级增删改与主账号切换。

### 6.3 手工窗口能力

- 支持手工新增、清空窗口。
- 作为官方接口不可用时的标准降级路径。

## 7. 安全与存储

- 允许使用 macOS Keychain 存储密钥信息。
- 允许将非敏感信息（如 Base URL）存于本地配置文件。

## 8. `new_api` 接入要求（按官方接口）

### 8.1 数据源与鉴权

`new_api` 账号必须基于以下固定接口：

1. `GET https://<BASE_URL>/api/user/self`
2. `GET https://<BASE_URL>/api/token/`（分页）

两类接口统一使用：

- `Authorization: Bearer <用户级系统访问令牌>`
- `New-Api-User: <用户ID>`

### 8.2 配置交互（单弹窗）

- 该约束仅适用于 `new_api`。
- 新增账号必须在同一弹窗输入：
  - 账号名称
  - Base URL
  - 用户 ID
  - 用户级系统访问令牌
- 单弹窗提供：
  - `测试连接` 按钮（只测试，不保存）
  - `保存配置` 按钮

### 8.3 三级校验（红绿灯）

测试连接必须输出三级结果（🟢/🔴）：

1. **一级：API 可达**
   - Base URL 可收到 HTTP 状态码即视为可达。
2. **二级：`/api/user/self` 可用**
   - 使用用户 ID + 用户级令牌访问该接口并返回有效用户数据（至少包含 `quota`）。
3. **三级：`/api/token/` 可用**
   - 能访问 token 列表接口并解析出 token 列表结构（至少包含 `remain_quota` 字段）。

保存门禁：

- 仅当三级全绿才允许保存。

### 8.4 分页要求（token 列表）

`/api/token/` 为分页接口，必须根据返回的 `page`、`page_size`、`total` 判断是否翻页并拉取完整数据。

### 8.5 展示要求

每个 `new_api` 账号展示：

1. **钱包余额**
   - 使用 `quota` 字段
   - 单位换算：`quota / 500000 = USD`
2. **每个已启用 token（`status=1`）**
   - 名称
   - 剩余额度（`remain_quota`，按 USD 展示）
   - 总额度（`remain_quota + used_quota`，按 USD 展示）
   - 过期时间（`expired_time`）

说明：

- `status=1` 视为已启用；即使过期也仍需展示。

## 9. 非目标（当前阶段）

- 不优先实现基于非官方接口的稳定自动采集。
- 不优先实现本地日志解析链路。
- 不要求恢复或优先维护旧的 Claude Code 专用路径。

## 10. 迭代原则

- 以“可扩展性”和“贡献者易接入”为第一优先。
- 每次新增平台或能力时，先补充本 spec，再实现代码与 README 使用说明。
